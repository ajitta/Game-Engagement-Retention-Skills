# Analysis: What Is Wrong With v1.1.0

A blind A/B against a plain-model baseline — one prompt per skill, Korean, judged without knowing which arm was which — put the skill arm behind in all three matchups, every margin recorded as "small". That result is the spine of this document, and it needs its limits stated in the same breath: n=1 per skill with a single judge is a directional signal, not a verdict. It does not show the skills are worthless; the same judges called the skill arm's ethics work and return-event discipline the sharpest contributions in either arm. What it does show is that the plugin's rigor is being delivered in a shape and with a content depth that lose to an unassisted model on the things a PM acts on: a ship path, effort, magnitudes, and a legible document. Behind the A/B sit 33 merged findings from seven critic lenses; adversarial verification reached M01–M13 and refuted one of them outright (M11), contested another (M07), and cut the severity of four. M14–M33 were never adversarially verified and are marked PLAUSIBLE throughout. Read this as: the skeleton is right, the flesh and the format are not.

---

## 1. How this was tested — method and its limits

Five instruments, with very different evidential weight.

**Seven critic lenses.** Static reads of the repo by lens — routing, templates, skill-craft, games content, apps/ethics, facts/citations, packaging — producing 80-odd raw findings merged into M01–M33 with evidence quotes at file:line. Static reading finds absences reliably (a grep for `accessib|reduced.?motion|photosensit|colorblind` over `skills/` returns zero hits, and that is a fact) and infers impact unreliably.

**A 30-request routing test.** 30 requests (English and Korean) run against the routing contract; 28 matched the expected route. This was **model-simulated**, not an installed-plugin trigger test: it exercises whether the written rule decides correctly, not whether Claude Code's skill listing actually fires the right skill in a live session. The two non-matches were deliberate ambiguity probes — meta-progression (#12, went to the advisor where no owner is defined) and ARPDAU (#17, no skill fired). Two further outright misses were recorded inside the 30: analytics instrumentation (#26) and a metric-definition comparison (#27), both landing on no skill.

**A three-prompt blind A/B.** One prompt per skill: a puzzle-RPG skill-gauge moment (interaction-reward-moments), a casual collection RPG D3–D7 churn plus battle-pass decision (retention-strategy-designer), and a daily 사주 app moment + return + ad load (engagement-retention-advisor). Skill arm vs plain-model arm, Korean prompts, blind judging, one judge per pair. The skill arm lost all three at small margins. **n=1 per skill, one judge, no repetitions, no pre-registered rubric** — the correct reading is "the shipped texts do not currently beat a plain model on these three prompts", not "the skills are worse than nothing".

**Adversarial verification.** Each of M01–M13 was handed to verifiers instructed to break it. This changed the picture materially: M11 was refuted on its load-bearing premise, M07 split, and M03/M04/M08 (and M06/M09 in one verdict each) were dropped from high to medium. M14–M33 did not get this treatment.

**Live tool probes on Claude Code 2.1.261.** Loader extraction from the installed binary, `claude plugin details` token measurement, `claude plugin validate` target behavior, `claude plugin eval --help`. These are the only claims in this pass with no interpretive gap.

## 2. What works and must survive the rewrite

Every item below was produced by the skill arm and named by a judge or a verifier as something the baseline did not have. The rewrite is a merge, not a replacement.

**Return-event rigor.** The ADV judge: "Defines the return event rigorously and defends it against gaming ... B never defines a return event at all." The RSD judge: "리턴 이벤트 재정의가 두 답변 통틀어 가장 날카로운 한 수 ... 앱 오픈은 푸시로 부풀릴 수 있고 컬렉션이 말라붙는 것을 가린다." — *Do not lose this: the return event stays a mandatory, defended field with its own slot in the output, not a metric bullet.*

**Cohort, holdout and novelty discipline.** Same-week cohorts, a kept holdout, 2–4 week novelty windows, one pre-registered primary metric, intent-to-treat judgment that names self-selection bias, and resurrection success defined as +30d re-dormancy rather than the comeback click. None of this appeared in any baseline arm. — *Do not lose this: preserve the wording verbatim and move it from the reference files into the workflow, where it will actually fire.*

**Guardrail metrics beyond crash rate.** Opt-out rate, notification-permission revocation, uninstall, refund rate, review-keyword frequency for 강제/부담/매일, pressure-revenue detection, and 4+ sessions/day read as an alarm rather than a win. — *Do not lose this: user-harm telemetry is the plugin's most defensible product feature and no baseline produced anything like it.*

**Ethics specificity.** IRM judge: "Best ethics work in either answer, and it is specific rather than a disclaimer: names the exact dark pattern (selling gauge instant-charge / hold-loss protection / VFX skip = 좌절-해소 과금), and then re-lists it as a *failure signal* in the metrics section." RSD judge: "윤리 판정이 구체적이고 검증 가능", plus "매출 트레이드오프를 은폐하지 않고 사전 합의 사항으로 못박음" — it prices the revenue cost of the ethical option. — *Do not lose this: D1's tiering changes when refusal fires, never that ethics judgments are named, mechanic-specific, and wired to an observable failure signal.*

**Progressive disclosure is correctly built.** SKILL.md bodies are 82–105 lines with depth in `references/`, names match directories, `argument-hint` is present, `allowed-tools` was correctly dropped so the Skill-tool hand-off is callable, and 31 cited URLs check out with 0 dead. — *Do not lose this: v2 adds reference files, it does not grow the SKILL.md bodies past the 500-line guidance.*

**The routing rule.** 28/30, including the hard motivation-vs-deliverable case ("D7 is low, I want to make the level-complete screen more satisfying" → interaction-reward-moments), the paired complaint, compare-or-prioritize, quit-mid-session, and all three Korean requests despite zero Korean trigger phrases in any description. The core — *route on the deliverable, treat the cited metric as motivation* — is stated consistently across all seven places it appears and does not drift. — *Do not lose this: the deliverable-first rule is the plugin's best-tested asset; v2 extends its coverage and must not restate its principle.*

**Benchmark hedges limited the damage of M10.** `retention-playbook.md:3` ("never as targets"), `:49` ("verify before quoting exact decimals") and `:62` ("every row relays vendor data") are why the skill arm read D1 38% correctly as a strength while the baseline invented a "D1 44~46% 건강 기준" and set a target off it. — *Do not lose this: fix the rows, keep the hedges.*

## 3. The findings, ranked

### M01 — The output table is the deliverable, and it collapses in a terminal (CONFIRMED, high)

Every skill's primary output is a wide markdown table: `interaction-reward-moments/SKILL.md:73` is 9 columns / 133 chars, `retention-strategy-designer/SKILL.md:58` is 10 columns / 131 chars, `engagement-retention-advisor/SKILL.md:60` is 9 columns / 194 chars. Verification corrected the finding's own title in its disfavor — the counts are 9/10/9, and the advisor's is the widest, not the narrowest. RSD is also the only one with no cell-length cap anywhere. All three blind judges named it: "the 9-column reward-moment table will wrap into mush in a terminal, and the columns that get crushed are exactly the high-value ones (작동 이유 / 검증 지표 / 리스크)"; "제안 5개를 담은 10열 표가 터미널·모바일에서 붕괴해 핵심 산출물이 가장 안 읽히는 형태가 됐고"; "in a terminal every cell wraps to 3-6 lines and the row boundaries disappear, which destroys the answer's centerpiece." The winning arms used 3–6 column tables and headed sections. Users are hurt precisely where the plugin adds value: the trigger → action → feedback → next hook → metric → guardrail chain is the part that becomes illegible, and Korean output makes it worse because each 한글 glyph takes two terminal columns. **Fix direction (settled by D4):** per-proposal card blocks, with any table capped at 5 columns for scanning only; the `pattern-library.md:196` mini example (354 chars on one row) is rewritten as a card so the model imitates the card, not the schema.

### M02 — The skill forces rigor and omits execution (CONFIRMED, high)

Verified absent by grep across all of `skills/` and `README.md`: `accessib`, `reduced.?motion`, `photosensit`, `colorblind`, `remote config`, `kill switch`, `rollout`, `rollback`, `sample size`, `MDE`, statistical power — zero hits each. `holdout` appears exactly once, at `retention-playbook.md:71`, i.e. in a reference file the model is merely invited to read, not in any workflow step. Judges: "No cost, no sequencing, no ship path"; "로드맵·타임라인·리소스 추정이 없음"; "No magnitudes anywhere. Impact is '高/中/低' with no baselines or expected deltas, so nothing here can be turned into a business case"; "No baseline measurement step. It goes straight to 기존 빌드 vs 신규 빌드 A/B without instrumenting the current build first." The accessibility hole is a safety defect rather than a preference, because the skill actively prescribes the effects that need the guardrail (`IRM SKILL.md:41` "Sensory game feel: hit stop, shake, sound, particles, haptics"). The user is hurt at the funding step: they cannot staff, sequence, size or roll back what the skill proposed. **Fix direction:** mandatory Sequencing (effort band, dependency, ship week, promotion evidence), an upgraded Measurement step (baseline instrumentation *before* the change, pre-registered primary metric, sample size/MDE or an explicit "underpowered — directional only", ≥2 usage cycles, week-3 novelty re-measure), and Ship safety (remote config for every tuned constant, staged rollout %, rollback thresholds with owners), plus accessibility and qualitative-method lines.

### M05 — LiveOps is routed in and has no content behind it (CONFIRMED, high)

`retention-strategy-designer/SKILL.md:3` and `:16` promise the route: "the named deliverable is a multi-day cadence mechanic (battle pass, login rewards, streaks, daily quests)". `retention-playbook.md` (117 lines, read in full) has no LiveOps, season, pass, quest or login-reward section; every repo hit for pass/quest/season is either a routing line or a prohibition (`domain-ethics.md:63`, `:71`). `LiveOps` has zero hits anywhere. The A/B made the consequence concrete: for a team evaluating a battle pass the skill arm produced "가격, 티어 수, XP 총량, 무료:유료 가치비, 완주율 목표, 캐치업 규모, 시즌 6주의 근거가 전부 부재. 요청의 절반에 철학으로만 답함", while the baseline delivered a 28-day season rationale, a $4.99 SKU, "완주 5,000pt vs 획득가능 6,500pt = 여유분 30%" and a no-gap season transition. This is the sharpest confirmed failure in the review: the 2026-07 pass added routing without adding the corpus, so the most frequent live-service ask reliably lands on a skill that can only say what not to do. **Fix direction:** `references/liveops-systems.md` — season anatomy, pass anatomy, quest pools, login/attendance calendars, event roster cadence, LiveOps metrics — including one worked 6-week season in the skill's own output format, so the ethics rules read as bounds on a real design.

### M06 — Genre-blind, platform-blind, and empty at D8–D30 (CONFIRMED, high; one verifier put it at medium)

`retention-playbook.md:46` is the entire mid-lifecycle corpus: "**D8-D30**: shallow content pipeline, no personalization deepening, no identity/social investment." Diagnosis with no lever. Greps across `skills/`: meta-progression 0, UGC 0, creator 0, clan 0, 4X 0, gacha 0, endgame 0, Steam 0, console 0, PC 0; `guild` twice, once as a moment trigger and once as a dark-pattern row at `retention-playbook.md:84`. The only game example in the playbook is "cleared a run" at line 17. The A/B: "D30 3%에 대한 구조적 처방이 없음: 5개 제안 어디에도 길드·친구·랭킹·엔드게임·경쟁이 없고 ... 두 숫자 중 더 심각한 D30/D7=0.27을 사실상 미처방", plus no technical or regional churn hypotheses at all. This matters because retention causes vary more by genre than by any other axis, the Korean charts are dominated by exactly the genres with no profile here, and the plugin's own manifest says "for games and interactive apps". **Fix direction (settled by D3 — go game-deep):** `references/genre-profiles.md` per genre (natural return event, cadence, benchmark band, dominant churn cause, first diagnostic, two high-leverage ethical mechanics), a three-part D8–D30 expansion (meta-progression pacing, social systems as retention drivers, content-cliff detection), and a Platform notes block, since the notification guidance at `RSD SKILL.md:78` is mobile-only.

### M08 — Absolute prohibitions with no threshold and no compliant spec (CONFIRMED core, severity adjusted high → medium)

`domain-ethics.md:65` forbids "Metered-access (energy/stamina) systems whose refill timing is tuned to dictate return cadence" — every shipped energy system tunes refill against cadence, so no configuration passes. `:63` forbids pass tracks "whose daily/weekly quest expiry demands daily play" with no threshold on "demands". `:78`'s absence test, read literally, condemns Korean 기다리면 무료 — the dominant lawful model in the plugin's own interactive-narrative domain; grep for 기다리 or wait-or-pay across `skills/` returns nothing. `:37` turns on unobservable intent ("engineered *solely* to force next-session opens"). Verification cut two limbs: the paid streak freeze at `:54` states its rationale inline and `git show 195f9bb` shows it was a deliberate addition, and the Fortnite pass reading was a misread. What survives is structural and is what hurts users: no harm-reduction gradient, and no acceptable version to redesign *toward*, so the skill can only refuse a business model it cannot replace. **Fix direction (settled by D1):** convert each absolute into a bounded, measurable spec with an "acceptable version" under Preferred — energy refill within one natural inter-session gap with a free activity before any purchase surface; pass completable at ≤3 play days/week with daily-expiring quests ≤~20% of track XP; one-shot events with an earnable equivalent and a ≥14-day window; an explicit 기다리면 무료 carve-out in the narrative section.

### M09 — The users' own jurisdiction is the one never named (CONFIRMED, high; one verifier at medium)

A grep for `korea|한국|확률|게임산업|정보통신망|jurisdiction|counsel|GRAC` across all 1,015 lines of skill content returns exactly three hits, all of them the "Korean input → Korean output" language contract. `retention-playbook.md:117` lists loot-box regulation for "Belgium/Netherlands/Brazil/Australia/EU" — Korea absent. `pattern-library.md:42` says "disclose odds when stakes are meaningful", where Korean law makes disclosure mandatory regardless of stakes and covers 강화/합성 outcomes, not only capsules. The A/B surfaced a live example neither arm caught: 정보통신망법 requires separate 야간 수신동의 for 광고성 정보 between 21:00 and 08:00, which lands directly on the personalized wake-time push the skill itself recommends. The plugin already asserts regulatory awareness, so the silence is selective, not a scope boundary — and that is the worst kind of near-miss: the rules it cites are foreign, and the rules that bind its audience by default are missing. **Fix direction:** a dated "Regulation snapshot (verify with counsel)" block, one line each — GIPA Art. 33 odds disclosure, 정보통신망법 night-time advertising consent and the 광고성 vs 정보성 distinction, AI Basic Act Art. 31, PEGI 2026 interactive-risk categories, Brazil ECA Digital — plus a jurisdiction flag on the tiered ethics response.

### M10 — The benchmark table is internally contradictory and partly misattributed (CONFIRMED, high)

The finding survives on repo-internal arithmetic alone. Inside one five-row table: games top quartile D1 ~26.5–27.7% (`retention-playbook.md:55`), games global median D1 ~22% (`:56`), and "Consumer apps, cross-industry median" D1 ~25–26% (`:57`). A cross-vertical median cannot sit at the top quartile of games and above the games median. Line 57 is sourced to "Adjust Mobile App Trends 2026" but traced (`:107`) to a `core-mba.pro` aggregator; Adjust's own 2026 report publishes only per-vertical figures. Lines 55–56 cite a Substack summary of the *2025* GameAnalytics report while the 2026 primary reports a materially different band. Line 64's "~7% retention rule" has no source in the Sources block at all. Three unreconciled all-app D30 values coexist (5–7%, ~2.1%, ~4%), so "what's a normal D30?" has three answers in one file. A PM reads a benchmark as a pass/fail bar; the A/B judge caught the skill arm violating its own rule — "벤치마크 버티컬 혼용 ... 본인이 부기한 '버티컬을 밝히라'는 규율을 스스로 위반". **Fix direction:** rebuild from primaries with per-vertical rows and percentile bands, change the column header to "Source (data year)", delete the 7% rule and replace it with "PMF signal = the curve flattening; the level is vertical-specific".

### M12 — The AI-companion section misses the best-documented companion dark pattern (CONFIRMED, high)

`domain-ethics.md:22-26` lists exactly four Forbidden bullets for AI Companion: dependency engineering, over-notification, crisis-role confusion, sensitive-data exploitation. There is no rule about the exit moment and no rule about purchase or paywall — while 사주 gets one (`:10`, "no purchase surface on the same screen or session segment as a negative reading") and visual novel gets one (`:39`). Session-end handling sits under Preferred (`:30`, `:73`), not Forbidden. A grep for `minor|under[-]?age|child|teen|age[- ]gat|parent` across `skills/` and `README.md` returns zero relevant hits, as does any search for AI-identity disclosure. So "how do we keep users from ending the chat?" — the highest-yield retention lever in this domain, and the one with the strongest external evidence of manipulation — passes every Forbidden bullet, and a Korean PM building a companion or journaling app gets no prompt to age-gate, disclose AI identity, or avoid therapy positioning in a year when several of those became legal duties in markets they ship to. **Fix direction:** add a farewell-manipulation prohibition, a paywalled-memory/affection prohibition, a dated legal-baseline block, and a sixth universal check ("could a minor be in the audience?").

### M03 — No executable eval, and the README's validation row is unreproduced (CONFIRMED core, adjusted high → medium)

`ls evals` → no such directory; `git ls-files` returns 13 files, none of them a case, grader or transcript. `IMPLEMENTATION_NOTES.md:22` puts the triad re-run under "Not done (out of scope)". Verification then refuted the finding's own headline. This pass's A/B is n=1 per prompt with margins self-reported as "small", judged inside the same pass arguing the skill is weak; the README's claim is n=2 self-labelled. **Two noise-level results do not falsify each other.** The defensible statement about `README.md:70` is "unreproduced and not currently supported", not "false" — and publishing "0/3" as fact would repeat the defect being criticized. The real harm is narrower: routing and refuse-and-redesign have been rewritten twice (`7f2b3fc`, `195f9bb`) with nothing encoded, so the v2 rewrite has no regression net. **Fix direction:** commit `evals/<case>/prompt.md` + `graders/criteria.md` for the 30 routing requests, the adversarial-ethics prompts, six *false-positive* ethics cases, and the three A/B prompts with rubric graders for card format, sequencing and baseline-first measurement. Note the constraint: `claude plugin eval` printed "currently in early access" and scaffolded nothing on this machine, so cases can be authored and version-controlled but must be run manually for now.

### M04 — Monetization has no home (CONFIRMED core, adjusted high → medium)

`grep -rniE 'ARPDAU|ARPU|LTV|eCPM|IAP|gacha|loot ?box'` over `README.md` and `skills/` returns zero hits in skill content. All eight monetization/ad mentions are prohibitive: `IRM SKILL.md:55`, `RSD SKILL.md:76`, `:80`, `ADV SKILL.md:41`, `:43`, `retention-playbook.md:47`, `:82`, `domain-ethics.md:64`. There is not one line anywhere stating when an ad or purchase surface *is* acceptable. Routing test #17 ("Increase our ARPDAU without hurting retention") fired no skill at all. In the A/B, the advisor "largely declines the third of the three things the client asked for" — 광고 매출 의존도 got a refusal list and nothing else — while the baseline won partly on "LTV = ARPDAU × Σ R(d)" with a worked breakeven. Users are hurt twice: either no skill fires and the highest-risk area gets an unguarded plain-model answer, or one fires and answers two thirds of the question. **Fix direction (settled by D2 — in scope as retention tension only):** RSD takes explicit ownership of the trade-off (ARPDAU/LTV vs D7, ad load, gacha/offer cadence, first purchase, paywall effects), with an `LTV = ARPDAU × Σ retention` framing block and a guardrail line separating "trade-off analysis → answer it with the frame and the bounds" from "pressure-mechanic request → refuse-and-redesign". No standalone monetization-design module.

### M13 — Retention metrics are never defined (CONFIRMED on content, routing half refuted; medium)

A case-insensitive grep for `rolling|classic|DAU|MAU|stickiness|D28|triangle|unbounded` across all `skills/` markdown returns zero hits. `retention-playbook.md:53` is `| Segment | D1 | D7 | D30 | Source (year) |`, sourced to GameAnalytics, which reports D28 with install day = Day 0 under classic retention — none of which is stated. `RSD SKILL.md:66` asks for "D1 / D7 / D30 (or W1/W4 ...)" with no definition. The same app reads 43% or 32% D1 depending only on the day convention (Amplitude, 2025, https://amplitude.com/docs/analytics/charts/retention-analysis/retention-analysis-time). Every retention conversation starts with a pasted number, and Korean studios routinely mix Adjust/AppsFlyer, Firebase and in-house BI — so definition mismatch is the norm, and the skill compares apples to oranges against benchmarks that are themselves misattributed (M10). The routing half of the finding was refuted: #27 landing on no skill is a scope question, not a routing bug. **Fix direction:** a "Metric Definitions" subsection before the benchmark table (classic vs rolling vs bracket; the day convention; DAU/MAU bands; how to read a cohort triangle), plus one workflow rule — ask which definition and which tool produced the user's number before comparing anything.

## 4. Findings that did not survive verification

**M11 — REFUTED.** The claim was that bare relative references (`../interaction-reward-moments/SKILL.md`, `references/domain-ethics.md`) resolve against the user's project directory at invoke time and fail silently. Loader extraction from the installed binary at `/Users/chosh/.local/share/claude/versions/2.1.261` shows Claude Code prefixes the skill body with `Base directory for this skill: <dirname of SKILL.md>` for **both** plugin skills and filesystem skills. The finding's supporting observation ("an invocation returned only `Launching skill: <name>`") confused the tool-result string with the injected content — the body arrives separately, already prefixed. The same excerpts show `${CLAUDE_SKILL_DIR}` substitution is gated on exactly the same condition as the base-directory prefix, so the placeholder buys no coverage the base-directory line does not already provide. The refutation carries convention evidence too: the official Anthropic marketplace ships the same cross-skill sibling pattern (`mcp-server-dev/skills/build-mcp-app/SKILL.md:59`, "See `../build-mcp-server/references/elicitation.md`"), and `skill-creator` uses bare `references/…`. **Consequence for v2: do not describe the paths as broken, and do not budget a fix for a bug.** Switching to `${CLAUDE_SKILL_DIR}` remains defensible as explicitness, and the separate half of M11 — the "(if installed)" / "If absent, judge using the Guardrails above" hedge at `IRM SKILL.md:105` and `RSD SKILL.md:12` — survives on its own merits, because `README.md:11` says the three ship together and the hedge licenses a weaker rule set (see M19).

**M07 — CONTESTED.** *Refuter:* "single-tier" misreads the protocol. `domain-ethics.md:83` and `:85` are two different paths, not one severity: `:83` governs proposals the skill itself generates (relabel and offer the alternative, which lands in the advisor's existing "Items to view separately" bucket, with no lecture to the user); `:85` fires only when the user's own request is a forbidden pattern. `IRM SKILL.md:54-56` already splits severity explicitly — "→ do not recommend" versus "→ flag". Two of the five over-refusal examples were misreads: `domain-ethics.md:54` places free or earned streak freezes under **Preferred** and forbids only the sold variant, and 기다리면 무료 appears in no forbidden list. And the Tier-B proposal reverses a documented decision: `git show 195f9bb` records the 2026-07 pass deliberately adding those exact prohibitions. *Supporter:* the accurate, narrower claim still stands — there is no severity graduation *within* the forbidden set, and the refusal protocol keys off "is it on the list", not "how bad is it". The strongest evidence is one the original finding missed: **route-in-then-refuse.** `RSD SKILL.md:3` advertises battle passes, login rewards, streaks and daily quests as what routes *to* the skill, while `domain-ethics.md:63` and `RSD SKILL.md:76` forbid their standard implementation. The plugin recruits the work by name and then forbids it. Also verified: `README.md:66-72`'s triad has no over-refusal row — the only ethics evidence on record is one-directional *and* stale. **Consequence for v2:** D1's four-tier model is a deliberate re-decision, not a bug fix; the analysis should not claim the current stance is an error, and the rewrite must ship false-positive eval cases so the new calibration is tested in both directions.

**Severity adjusted down:** M03 high → medium (the "falsifies the README" framing refuted; the missing regression net survives), M04 high → medium, M08 high → medium (paid-freeze and Fortnite limbs cut), M06 and M09 mixed high/medium across verifiers. None of these were withdrawn; all keep their fix direction.

## 7. Root causes

**1. The table was chosen as the deliverable before the medium was considered.** A 9- or 10-column schema is an excellent *authoring* checklist — it makes the model fill trigger, feedback, next hook, metric and guardrail for every item, which is exactly the rigor the plugin exists to force. It is a terrible *reading* format in an 80-column terminal, and worse in Korean. Fixing the format alone does not lose the checklist; it separates the two jobs. This single choice produced M01, most of M24, and the "reads like a filled template" verdict in all three A/B runs.

**2. Ethics was encoded as a prohibition list rather than as bounded specs.** A list can only say no. Because no bullet carries a measurable threshold — "tuned to dictate return cadence", "demands daily play", "engineered *solely*" — there is no configuration of a standard mechanic that passes, and no compliant version to redesign toward. That forces the skill to refuse business models rather than shape them (M08), leaves the false-positive direction untested (M07), and produced the route-in-then-refuse contradiction where RSD advertises battle passes and then forbids their standard implementation. It also explains the shape of M04: with monetization present only in prohibitions, the plugin has no vocabulary for the trade-off, even though the ethical case is strongest when it is made in the PM's own currency.

**3. Routing outran content, and duplicated text drifted.** The 2026-07 pass added routes (cadence mechanics), tightened prohibitions, and added no positive design corpus. So the plugin now recruits the highest-frequency live-service asks — battle pass, LiveOps calendar, streaks — into a skill whose reference file has no section for any of them (M05). The same pass edited some of the three triplicated routing blocks and not others (M20), and spread ethics across seven locations that have already diverged (M19). Both are the predictable cost of hand-synchronized copies with no check.

**4. Nothing in the repo is re-checkable.** There are no eval cases, so two rewrites of the routing and refusal text shipped with no regression net (M03). The benchmark rows were sourced through aggregators and SEO summaries rather than the vendors' own reports, so one table now contradicts itself and cannot be re-derived (M10). Four citations are mis-described (M26, PLAUSIBLE). The headline validation evidence lives in private notes the repo says it does not contain (`README.md:58`). Every other defect in this document is a thing that could have been caught; this is the reason none of them were. It is also the one root cause whose fix is a precondition for the rest: without committed cases, the v2 rewrite cannot be shown to improve anything, and the next pass will regress silently in exactly the same way.
